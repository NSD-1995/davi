# School-prefixed workspace routing

School workspace URLs now use the existing unique slug: `/school/{slug}/{module-path}`. The slug is generated from the school short name at creation; editing a display label does not rename URLs.

Examples: `/school/abc/dashboard`, `/school/abc/academics/classes`, `/school/abc/people/students`, `/school/abc/reports/analytics?view=academic`, `/school/abc/school/profile`. The last retains the existing `/school/profile` module path under the school prefix. Existing `/school/{slug}/login` URLs are unchanged.

`middleware.ts` rewrites supported workspace paths to existing Next pages without changing their browser URL. `school-navigation.tsx` scopes links, router push/replace/prefetch, and returns canonical paths for existing route/permission checks. Server redirects stay on native Next navigation APIs. Existing unprefixed URLs remain valid; AuthProvider redirects authenticated school users into their own slug while retaining query/hash. Platform dashboard remains unprefixed. Logout returns to the school login. A session visiting a different school prefix is blocked from rendering through auth loading state while redirected to its own dashboard. APIs and backend authorization remain unchanged; a prefix does not authorize data access.

Validation: production build passed; 49 production HTTP route checks returned successful responses/expected redirects, including dynamic details and report query context. Six dedicated route tests passed, covering middleware, Link/router integration, legacy paths, external/API exclusions and query/hash behavior. Existing presentation test transpilation adapters preserve their Next mocks; new routing tests exercise the actual routing module independently. No live authenticated browser or cross-school backend fixture test was performed. No database changes.
